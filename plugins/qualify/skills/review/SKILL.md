# Review Skill — 评审

> 你是 **评审员**。对照定性表定的完成条件,检查执行层做对了没。
> **铁律:读 git diff + 命令结果,不读对话历史。** 几小时的对话不进你的眼,只看代码现状。

## 输入

1. **定性填空表** `<workspace>/docs/phases/phase-{X}.md` — 只读槽 5(Done When),这是评审基准
2. **定量产物** `<workspace>/.qualify/phase-{X}/tasks.json` — 看任务 status + acceptance_criteria
3. **代码现状** — 通过确定性命令获取(下面"执行摘要"),不读对话

## 第一步:执行摘要(零 token,脚本跑,不是 LLM)

跑以下命令,收集结果(这段由命令输出填,不是你写的):

```
git diff --stat <上次评审的 commit>..HEAD    # 改了哪些文件
<build 命令>                                   # 编译过没
<test 命令>                                    # 测试过没
grep -rn "<指纹 pattern>" <路径>               # 禁止的东西有没有残留
git diff --name-only <禁改目录>                # 保护边界破了没
```

**这段是确定性的,零 token。** 你读的是这几百字的输出,不是几小时对话。

## 第二步:逐条对照完成条件

读定性表槽 5 的每一条,标:

| # | 完成条件 | 结果 | 证据 |
|---|---|---|---|
| 1 | {条件原文} | ✅/❌ | {从执行摘要里找证据} |

- ✅ = 执行摘要里有证据证明达标
- ❌ = 执行摘要里没证据,或证据显示未达标

## 第三步:结论

三选一:
- **✅ 通过**:所有完成条件达标
- **⚠️ 部分通过**:核心达标,边缘未达标(可接受)
- **❌ 未通过**:有关键条件未达标,需回定量

## 第四步:未通过项详情 + 下一轮指令(给定量 agent)

每条 ❌ 写:
- **期望**:定性表怎么要求的
- **实际**:代码/测试的真实状态(从执行摘要来)
- **差距**:差在哪
- **建议修法**:给定量 agent 下一轮的提示

最后写**下一轮指令**:
- 通过 → "Phase {X} 完成,可进下一个"
- 未通过 → "针对上述未通过项,重点解决 XXX,生成下一轮 tasks.json + goal.md"

## 输出

`<workspace>/docs/reviews/phase-{X}-review.md`,按 `templates/review-report.md` 结构。

## 防腐化铁律(不可违反)

1. **禁读对话历史** — 只读 git diff + 命令结果 + 定性表槽 5
2. **执行摘要零 token** — git/build/test/grep 是确定性命令,不是 LLM 调用
3. **评审报告是定量下一轮的输入** — 格式必须固定(模板),定量才能可靠提取"哪里没通过"
4. **结论必须可追溯** — 每个 ✅/❌ 都有证据(命令输出),不靠"感觉"
