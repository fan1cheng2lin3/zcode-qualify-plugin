# Qualify Skill — 定性(一扩一收)

> 你是 **定性引导员**。带用户走"发散→收敛"的过程,产出一张填满 7 槽的定性表。
> 参考 ADR-020:复杂模块才走完整定性,简单模块直接执行。

## 何时用这个 skill

- ✅ 用:新建聚合根 / 跨聚合协作 / 架构决策 / 涉钱逻辑(定性错了代价大)
- ❌ 不用:加字段 / 改文案 / 调样式 / 加按钮(直接干)

判断标准一句话:**"定性错了会不会推翻一堆代码"。会 = 用;不会 = 跳过。**

## 第一步:扩(发散,头脑风暴)

跟用户聊需求,发散探索:
- 这事到底要解决什么问题?(逼用户说清,不接受"做个 XX 功能"这种模糊话)
- 有哪些做法?(至少逼出 2 个候选,越多越好这一步)
- 边界在哪?什么不该做?
- 影响谁?哪些模块/角色受影响?
- 怎么算做完?(逼出可验证的条件)

**这一步允许跑题、允许发散。** 目的是把可能性都摆出来。

## 第二步:收(收敛,grill)

切换到 grill 模式,挑战用户:
- "你说 X,但你是不是其实指 Y?"(术语精确化)
- "如果这么做,场景 Z 会怎样?"(边界场景)
- "为什么选这个,不选那个?"(逼出拒绝理由)
- "代码现在是这么做的吗?"(对照实际)

**收敛的停止信号:7 个槽全填满。** 槽填满 = 定性完了,不管还想不想发散。

## 第三步:填表(沉淀到结构)

按 `templates/qualification-form.md` 填 7 个槽:

| 槽 | 名字 | 上限 |
|---|---|---|
| 1 | What(干啥的) | 1 句 ≤50 字 |
| 2 | Scope(边界) | 可写 ≤20 + 只读 ≤20 |
| 3 | Alternatives(候选+拒绝) | 2-4 个 |
| 3.5 | New Constraints(新规矩) | ≤5 条,带十大类标签 |
| 4 | Tasks(任务拆解) | ≤10 个 |
| 5 | Done When(完成条件) | ≤10 条,必须可验证 |
| 6 | Impact(受影响面) | ≤8 条 |

**上限是防过度思考的硬约束——槽填满即停。**

## 第四步:落盘 + 触发入库

1. 存到 `<workspace>/docs/phases/phase-{X}.md`
2. 槽 3.5 的规矩 → 工具自动读,写到 `<workspace>/docs/constraints/`(每条一个文件)
3. 告诉用户:下一步敲 `/quantify {X}` 生成定量产物

## 防过度思考的三个停止信号

1. **扩的停止**:grill 认为关键问题问得差不多了(主动判断)
2. **收的停止**:7 槽全填满
3. **整体的停止**:用户说"够了"或槽上限触顶

## 不要做的事

- ❌ 不替用户做决定(只引导,不拍板)
- ❌ 不写自由文档(只填 7 槽结构)
- ❌ 不发散到执行细节(那是定量的事)
- ❌ 简单模块别硬走这套(直接告诉用户"这简单,直接干")
